# Submission walkthrough (8–12 minutes)

This is a recording guide, not a claim that a Loom has been recorded. Use synthetic data and keep `.env`, credentials and developer consoles containing request headers off screen.

1. **0:00–1:00 — Product and boundary.** Explain the two businesses and “agents draft; code decides.” Show Inbox, Quality, Activity and Settings. State that identity and delivery are local simulations.
2. **1:00–3:00 — Receive and draft.** Submit a new synthetic phone or laptop enquiry. Show queued → preparing → held draft. Open extraction, catalogue evidence and totals. Explain the one structured model call and exact source arithmetic.
3. **3:00–4:00 — Duplicates and correction.** Run `bun run replay:seed` twice concurrently. Show receipt history and deduplicated provider identity; explain why existing seeded events do not spend again. Use a fresh test conversation to change 25 laptops to 30 and show the old pending draft superseded.
4. **4:00–5:30 — Human decision and outbox.** Open the same pending item in two tabs. Edit safe wording and approve with a named demo reviewer. The second stale approval must lose. Show `Sent · simulated` with one persistent simulation ID, and the saved Unicode edit/review in Activity.
5. **5:30–7:30 — Prove.** Select the current accepted baseline for each business. Show cases, hard checks, Arabic slice, real response IDs, judge dimensions and genuinely saved human labels/agreement. Explain one actual judge disagreement or early-run failure and what changed.
6. **7:30–9:00 — Regression and trust.** Select a degraded candidate and show blocked gate, hard failures and previously passing regressions. Run `bun run eval:verify` without a key. For a fresh paid demonstration use `bun run eval:gate --degraded`; expect exit 1 and do not accept it. Show version-bound supervision history. Explain that a failed unused candidate does not inherit the accepted version's promotion; a failed current version revokes its own trust and pending automatic work is cancelled.
7. **9:00–10:00 — Isolation and limits.** Trace `evt_0010/0011`: Rimal receiving destination wins over claimed Qamar identity and never gains Qamar catalogue access. Explain the RLS/omitted-filter tests and Arabic depth choice. End with the hardest tradeoff: controlled templates and supervised commercial replies limit scope while preserving a complete auditable local spine.

Before submitting: complete at least five independent output labels per business, export their real evidence with `bun run eval:export`, verify `bun run check`, `bun run db:test` and `bun run eval:verify`, record the Loom, and review the Git diff/history. Do not claim independent human sign-off or a recorded video before they exist. Commit/push only after the repository owner requests them.
