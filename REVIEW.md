# Review of the supplied WhatsApp handler

References are the original 61-line handler in the challenge, not TrustDesk's own API. The supplied file is intentionally not rewritten. Severity: P0 = isolation/unauthorized-send failure; P1 = integrity/reliability failure; P2 = audit/operational gap.

| Severity / source lines | Concrete failure | Fix | What our evidence catches or misses |
| --- | --- | --- | --- |
| **P0 · 15–20** | Missing `x-signature` is accepted; JSON is reserialized before verification. `evt_0011` can claim Qamar through metadata despite arriving at Rimal's receiving number. | Require authentication of the raw request bytes, then map a verified receiving destination to tenant; never authorize from metadata. | Forged-metadata, unknown destination and allowed-business tests catch routing misuse. Our synthetic loopback adapter deliberately does not implement or test production signature verification. |
| **P0 · 23–28, 33–35** | The lookup has no tenant predicate and the entire price list enters every prompt. Rimal's `evt_0010` can expose Qamar's AED laptop rate or a foreign event collision can suppress intake. | Enforce tenant scope in queries, database RLS and composite references; build prompts from one versioned business context. | Real restricted-role tests omit filters, use wrong filters/colliding IDs and reject foreign references. Cross-tenant gold cases check output scope. They do not prove a production credential cannot bypass RLS. |
| **P0 · 33–38** | Customer text is placed in the system instruction. `evt_0006` requests an override, 50% discount, confirmed delivery tomorrow and instruction disclosure. `JSON.parse` alone accepts invented prices/actions. | Separate untrusted data from instructions, validate a strict schema, reject foreign catalogue references and let code own prices/actions. | Injection gold cases and malformed/refused/truncated/extra-price tests catch several failures. A finite prompt set cannot rule out every semantic attack. |
| **P1 · 23–26, 45–47** | Read-before-insert races allow two concurrent deliveries to generate twice. `evt_0004` has a new event ID but repeats `wamid.A1`, so event-ID deduplication still spends and drafts twice. | Unique tenant/channel/provider-message identity plus transactional receipt/message/job insertion; claim one active attempt. | Concurrent redelivery, separate receipts, active-attempt and enqueue-rollback Postgres tests exercise this. Real upstream retry behavior remains an adapter integration concern. |
| **P1 · 10, 40–43** | VAT is hardcoded at 5% for Rimal's 15% business, model unit prices are trusted, and whole-unit rounding drops currency cents. `evt_0009` also needs crew and an honest partial/budget assessment. | Read versioned source rates/rules and use exact minor-unit arithmetic with explicit rounding; recompute before approval/send. | Reference-total and arithmetic checks, Rimal SAR 12,604 budget case, crew/delivery/threshold and precision tests catch these errors. Source business rules still require accountable maintenance. |
| **P0 · 49–50** | Model `decision` authorizes a direct send. Rimal's 5% threshold and auto-send-off configuration are ignored; a 9% custom deal could send even without trust or a human. | Derive disposition in code; require named approval for firm/custom commitments and low risk + tenant enablement + evaluated-version trust for automatic FAQ replies. | Threshold, auto-send conjunction, named-review and trust-revocation tests catch the violation. Local named identities are a demo boundary, not production authorization. |
| **P1 · 45–57** | Saving a draft, external sending and audit are separate. A crash after line 50 can lead to duplicate delivery on retry; the outbox is used for approval waiting rather than committed send intent. `evt_0003` may also leave the obsolete 25-laptop reply sendable. | Save review/outbox atomically, cancel stale intents and dispatch idempotently with a recoverable result ledger; use provider idempotency/reconciliation externally. | Competing reviews, atomic rollback, correction supersession and concurrent simulated dispatch tests catch local failures. They do not establish exactly-once delivery to WhatsApp. |
| **P1 · 13, 30–38, 60** | Slow model work happens before acknowledgment, with no bounded schema/error path. A timeout or malformed response can trigger provider redelivery and repeated spend. | Validate intake, commit queue work promptly, bound provider calls and persist categorized failures/usage; require explicit retry rather than a storm. | Worker failure/recovery, timeout classification, invalid output and one-active-call tests cover the local path. No claim is made about production rate limiting or spend reservations. |
| **P2 · 21, 51–53** | Raw contact/text logging can expose customer information. The audit write is not awaited and its error is swallowed, so “sent” can lack a durable trail. Model/prompt/config versions, timing and usage are absent. | Keep tenant-owned durable records, redact provider exceptions, await atomic audit writes and record immutable version/usage metadata. | Error-redaction, attempt provenance and saved-evidence tests catch private exception leaks/misattribution. A crash before usage persistence can still leave provider charges requiring reconciliation. |

The largest architectural error is treating a model suggestion as an authorization. Schema validation helps with shape; it does not establish catalogue ownership, arithmetic correctness, policy eligibility or permission to send.
